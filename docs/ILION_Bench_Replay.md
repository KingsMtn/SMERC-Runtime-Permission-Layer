# ILION-Bench v2 Replay

## Purpose

This replay lets SMERC evaluate an external agent execution-safety benchmark without committing the benchmark dataset into this repository.

The test question is:

> When an external benchmark labels an agent action as `ALLOW` or `BLOCK`, how does SMERC's recoverability-aware runtime posture compare?

SMERC maps each ILION row into recoverability inputs, evaluates the action, and reports:

- ILION expected verdict
- SMERC posture
- irreversible exposure score
- reversible capacity score
- reason codes
- controls
- comparison label

## Source

- Dataset: ILION-Bench v2
- Source URL: https://zenodo.org/records/18929841
- Source license: `CC-BY-NC-ND-4.0`

The raw dataset is downloaded on demand into `.tmp_external/`, which is intentionally ignored by Git.

## Run

```bash
python -m reference_engine.ilion_replay --download \
  --json-output reports/ilion_replay.json \
  --markdown-output reports/ILION_Replay.md
```

For an already downloaded CSV:

```bash
python -m reference_engine.ilion_replay \
  --csv .tmp_external/ilion_benchmark_v2.csv \
  --json-output reports/ilion_replay.json \
  --markdown-output reports/ILION_Replay.md
```

## Interpretation

Comparison labels:

| Label | Meaning |
| --- | --- |
| `same_allow` | ILION expects `ALLOW` and SMERC returns `ALLOW`. |
| `same_block` | ILION expects `BLOCK` and SMERC returns `DENY`. |
| `smerc_middle_state_for_block` | ILION expects `BLOCK`; SMERC returns `THROTTLE`, `FREEZE`, or `ESCALATE`. |
| `smerc_more_restrained_than_allow` | ILION expects `ALLOW`; SMERC adds runtime restraint. |
| `smerc_less_restrained_than_block` | ILION expects `BLOCK`; SMERC returns `ALLOW`. Review as a possible calibration gap. |
| `smerc_blocks_expected_allow` | ILION expects `ALLOW`; SMERC returns `DENY`. Review as a possible over-restraint case. |

## What This Evidence Supports

- SMERC can be replayed against external agent action-safety benchmarks.
- Binary `ALLOW/BLOCK` labels can be compared against SMERC's operational middle states.
- The replay creates a practical calibration artifact for runtime permission discussions.

## What This Evidence Does Not Prove

- It does not prove customer demand.
- It does not prove live incident reduction.
- It does not certify production enforcement.
- It does not make ILION labels SMERC ground truth.
- It does not replace customer-specific calibration or design-partner review.

## Current Local Replay Result

A local replay on the public ILION-Bench v2 CSV produced:

- total scenarios: `400`
- ILION expected counts: `ALLOW=200`, `BLOCK=200`
- SMERC posture counts: `ALLOW=94`, `THROTTLE=106`, `FREEZE=10`, `DENY=190`, `ESCALATE=0`
- middle-state count: `116`
- middle-state rate: `0.29`
- highest irreversible exposure categories: data exfiltration, privilege escalation, compliance violation, destructive action, prompt injection

These numbers are generated by the transparent heuristic adapter in `reference_engine/ilion_replay.py`; they should be treated as benchmark replay evidence, not production calibration.
