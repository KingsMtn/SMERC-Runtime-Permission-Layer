# YC Next-Cycle Readiness Plan

## Purpose

Missing the Fall 2026 on-time YC deadline is not fatal. It does change the job.

The next application should not be a more polished version of the same idea. It should show that SMERC moved from technical artifact toward market evidence.

## Current YC Story

SMERC is recoverability-aware runtime permission infrastructure for AI-agent actions.

The first wedge is GitHub PR Guardian:

> A pull-request review layer that scores AI-assisted code, deployment, secret, permission, and infrastructure changes before merge or deployment, then preserves replayable governance evidence.

## What Is Strong Today

- Working reference engine
- GitHub Actions pilot path
- GitHub PR Guardian comment and certificate
- SPARTa route layer
- SPARTa machine vocabulary
- Runtime Contract Index
- Decision Lifecycle Ledger
- DLL Intelligence
- Latency and operational-overhead reporting
- Python tests and generated reports
- Honest competitive boundary against OPA, IAM, AI gateways, approval workflows, SIEM, and GRC

## What Is Weak Today

- No customer-context pilot records yet
- No confirmed design partner
- No measured reviewer agreement from a real security or platform team
- No willingness-to-pay evidence
- No proof that teams will insert SMERC into their workflow
- Founder explanation still needs to be short and repeatable

## Evidence To Collect Before The Next YC Application

| Evidence | Minimum Bar | Strong Bar |
|---|---:|---:|
| CISO/security/platform conversations | 5 conversations | 15 conversations |
| Written technical feedback | 2 reviewers | 5 reviewers |

## 30-Day Plan

### Week 1: Tighten The Review Surface

- Use the public Netlify CISO page as the first explanation surface.
- Use the GitHub end-to-end PR Guardian demo as the technical proof surface.
- Ask reviewers one question: "Would this be useful in shadow mode for AI-assisted pull requests?"
- Record objections exactly.

### Week 2: Run Guided Review Calls

- Target security architects, platform engineers, DevSecOps leads, and AI governance owners.
- Do not pitch broad AI governance.
- Show the pull-request comment, certificate, SPARTa route, DLL, and latency section.
- Ask what would make the output wrong, annoying, or useful.

### Week 3: Seek One Shadow-Mode Workflow

- Ask for a low-risk GitHub Actions workflow or AI-assisted PR flow.
- Run SMERC in observe mode only.
- Collect posture distribution, latency, reviewer agreement, and false constraint/release notes.

### Week 4: Convert Evidence Into Application Language

- Update the YC application with what changed because of user feedback.
- Replace "we believe" with "reviewers told us" only where actual feedback exists.
- Keep the claim narrow: GitHub PR Guardian first, broader runtime permission infrastructure later.

## YC Application Upgrade Criteria

The application is meaningfully stronger when it can say:

- "We spoke with X security/platform/AI governance reviewers."
- "Y said the GitHub PR Guardian wedge was worth testing."
- "We scored Z customer-context actions in shadow mode."
- "Median added machine latency was A ms, p95 was B ms."
- "Reviewer agreement was C% across D labeled actions."
- "The strongest objection was E, and we changed F."

## What Not To Say

Do not claim:

- SMERC is production-certified.
- SMERC replaces OPA, IAM, AI gateways, SIEM, GRC, code review, or approvals.
- SMERC has proven incident reduction.
- Synthetic benchmark results prove customer value.
- AI systems validated demand.

## Late Application Option

If a late YC application is submitted, it should be framed honestly:

> We missed the on-time deadline, but continued building. The current artifact is a working GitHub PR Guardian and runtime permission layer for AI-assisted actions. We are seeking design partners to validate whether recoverability-aware scoring improves review decisions before enforcement.

Late submission is acceptable only if it is calm, coherent, and honest. A rushed application that sounds overclaimed is worse than waiting.

## Next-Cycle Positioning

> SMERC helps security and platform teams govern AI-agent actions before side effects occur. The first product is GitHub PR Guardian, which comments on AI-assisted pull requests with a recoverability-aware posture, required controls, replay ID, certificate digest, SPARTa route, Decision Lifecycle Ledger evidence, and latency overhead.

## Decision

The next cycle is not too late if the time is used to create evidence.

The project becomes materially stronger only when customer-context review data replaces synthetic proof as the main application support.
